## 实现与验证边界

领域类型位于 `lib/core/domain/models.dart`，SQLite 适配与业务命令位于 `lib/core/data/picker_store.dart`。数据库保留 JSON 语义载荷，并为排序、状态、提交序号、抽取时间、快照标题及实体关系保留 SQL 列；外键、唯一性和状态/时间、模式/轮次约束由 SQL 再次检查。所有写命令串行化，抽取记录和轮次消耗处于同一事务。恢复与清空提交后，在释放写队列前更新 generation。

`test/core/picker_store_test.dart` 共 23 项真实 SQLite 测试通过。它们验证业务语义和事务行为，不代替 Android 文件界面、动画、TalkBack 或性能验收。

## T10 损坏库修复补充

`lib/core/data/database_recovery.dart` 提供：

- `prepareBackup(text)`：内存库完整 JSON 校验并实际导入 SQL，返回不可变 `RecoveryBackup` 及数量预览，不访问原库。
- `recover(path, backup)`：必须先关闭原数据库句柄。在同目录新建替换库、完整导入、重新读取校验、关闭并执行 quick_check/foreign_key_check；随后写入不可变启动修复意图标记，将原 db、WAL、SHM 重命名为同目录 `.damaged-UUID` 文件，安装新库，核验后写入持久提交凭证。
- `recoverInterrupted(path)`：启动打开数据库前调用。未写提交凭证的中断保守恢复原文件副本，同时保留故障原件及替换候选；已有凭证且新库检查通过则保留新库。恢复复制中途再次中断可重复执行。损坏/超大/路径篡改的标记拒绝处理。

原故障文件不删除、不作为新库原地写入目标；仅生成的版本探测副本和完成的修复元数据可删除。SQLite 即使只读连接也可能重写 SHM，因此版本探测严格作用于原文件的临时副本。能识别的较新数据库版本拒绝覆盖，包括版本变化仅存在于真实 WAL 的情况。

`test/core/recovery_test.dart` 的 19 项测试：

1. 非法备份不触碰原文件。
2. 修复成功后原故障 db/WAL/SHM 逐字节保留；新库集合、记录、轮消耗及设置正确。
3–9. 在候选验证后、意图标记后、三个原文件分别移动后、原件全部保留后、新库安装后模拟进程中断，启动处理保守保留/恢复原件。
10. 提交凭证写入后中断，启动保留完整新库。
11. 替换普通异常立即回滚，同时保留原件和候选。
12. 标记 UUID 使用相对路径、Windows 反斜杠路径、绝对路径、非法 ID 或错误库名时拒绝，目录外哨兵文件不变。
13. 损坏、超大、不完整标记拒绝且原文件不变。
14. 较新 v2 数据库拒绝替换，数据库字节不变。
15. 首次安装中断不创建假空库，保留候选，可再次从备份修复。
16–18. 原库复制回滚的 db、WAL、SHM 三个阶段再次中断，下一次启动仍可恢复且保留原件。
19. 版本只存在于真实 SQLite WAL 时仍拒绝覆盖，db/WAL/SHM 全部字节不变。

宿主结果：19/19 通过；该服务及测试静态分析无问题。本测试覆盖模拟进程中断，不声称覆盖断电时设备文件系统的持久化顺序保证；Dart 文件写入使用 `flush:true`，文件移动均在同目录完成。不能替代 Android 杀进程与存储满的设备验收。
